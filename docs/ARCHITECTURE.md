# Архитектура Hostix

## Контекст

Hostix предоставляет единый CLI для запуска проектов в Docker-контейнерах и
Tart VM. Пользователь работает с одинаковыми командами, а различия жизненного
цикла контейнера и виртуальной машины остаются внутри runtime-адаптеров.

## Компоненты

- `cmd/hostix` — минимальная точка входа и обработка кода завершения.
- `internal/cli` — команды Cobra, валидация аргументов и представление результата.
- `internal/app` — сценарии приложения: порядок detect → build → replace → run.
- `internal/runtime` — общий контракт жизненного цикла изолированной среды.
- `internal/runtime/docker` — адаптер поддерживаемых Moby client/api модулей
  для Docker Engine API.
- `internal/runtime/tart` — будущий адаптер Tart CLI и SSH.
- `internal/doctor` — диагностика локального окружения без зависимости от CLI.
- `internal/detect` — определение Python-проектов и безопасной команды запуска.
- `internal/image` — генерация Dockerfile и временного TAR build context.

## Направление зависимостей

CLI координирует сценарии и зависит от интерфейса `Runtime`. Адаптеры реализуют
этот интерфейс, но не импортируются бизнес-логикой напрямую. Диагностика и
определение стека оформляются отдельными пакетами и тестируются без запуска
Docker или Tart.

```text
cmd/hostix -> internal/cli -> internal/app -> detect/image
                          |              -> runtime/docker
                          -> internal/doctor
internal/runtime <- docker/tart adapters
```

## Границы runtime-абстракции

В общий интерфейс входят только операции, имеющие смысл для обоих бэкендов:
создание, запуск, остановка, удаление, выполнение команды, чтение логов, статус
и список экземпляров. Сборка Tart image, SSH provisioning и детали Docker API
остаются внутри соответствующего адаптера.

## Производительность

MVP реализуется на Go. C++ и cgo не входят в обязательную архитектуру и могут
быть добавлены только после профилирования, если измерения покажут устойчивое
узкое место в обработке логов или агрегации метрик.
